Lingutribe 使用说明书

版本 v0.1.2（2026-08-15 更新）· 前端 React+TypeScript(Vite) · 后端 Node/Express（默认端口 8787）· 本地优先、可离线运行 · 已提供 macOS 桌面安装包（dmg）

阅读提示：本说明覆盖 Lingutribe 的全部已实现功能与操作细节。左侧为分类目录，点击章节可跳转；右侧正文随滚动自动高亮当前章节。文档中的端点路径、配置名、默认值均取自当前代码，可直接对照使用。
v0.1.2 更新内容（2026-08-15）：新增笔记（Notes）功能（第十四章）——Apple 备忘录式列表 + Markdown 编辑器，播放器与阅读器内联笔记自动保存；离线词典支持多词典选择（设置中指定用哪本解读，第九章）与 Reveal folder 一键打开词典目录；字幕断句优化（语音段最长 10 秒、短句自动并入下一段开头、9 秒静音切分，第五章 5.4）；STT 引擎稳定化为纯 Whisper（echogarden），移除了不稳定的旧引擎；本地 API 增加 CORS 白名单与词典容错；改库路径后无需重启即可生效。

一、产品定位与理念

Lingutribe 是一款本地优先（local-first）的语言学习工具，定位为"本地语言工作室"。它把听（音频/视频）、读（文章）、查（词典）、练（AI 对话与语法）、记（生词本与词频）整合在一个桌面/网页应用里，目标是让你在不依赖云端账号、数据留在自己机器的前提下完成外语沉浸学习。

  • 隐私 词典查询、本地 TTS（Kokoro）、本地 STT（Whisper）全部在本地运行，不联网。
  • 可选云端 仅当你主动配置 DeepSeek / OpenAI 等云端 LLM（或云端 TTS）时，才会向对应服务商发起请求。
  • 本地存储 所有资料、设置、对话记录都保存在你本机的"资料库"目录（默认 ~/Documents/LingoLibrary，打包版为 ~/Library/Application Support/Lingutribe/library）下的 SQLite 数据库与子文件夹中。
  • 可选桌面壳 提供 Electron 桌面壳与 macOS 安装包，本质仍是启动本地后端 + 打开浏览器窗口，端口固定 8787。

技术架构速览

二、快速开始

1. 环境要求（源码运行）

  • Node.js：建议 18+（项目已用 22.x 验证）。
  • ffmpeg：用于导入/转码与字幕处理。应用会自动在 /opt/homebrew/bin、/usr/local/bin、/usr/bin 或 PATH 中查找；缺失时 URL 导入与部分转写会失败。
  • yt-dlp（可选）：用于从 URL 导入视频/播客音频。未安装时仍可导入 RSS/文本类资源。

2. 安装与启动（源码）

# 进入项目目录
cd /Users/andy/WorkBuddy/lingutribe

# 安装依赖（仅首次）
npm install

# 生产模式：构建前端 + 启动后端（端口 8787）
npm run build
npm run start

# 或开发模式（热更新，同时跑 server + web）
npm run dev

# 桌面壳（可选）
npm run app

启动后浏览器打开 http://localhost:8787/ 即可使用。开发模式下后端会把它上面的网页请求实时代理到 Vite（5173），因此只访问 8787 一个地址就能看到热更新界面。Electron 模式会自动等待后端健康检查（最多 30 秒）后打开窗口。

3. 桌面安装包（dmg）

  • macOS（Apple Silicon）测试版安装包：Lingutribe-0.1.2-arm64.dmg。下载后双击挂载，把 Lingutribe.app 拖入"应用程序"文件夹。
  • 注意 当前为未签名测试版，首次打开可能被 Gatekeeper 拦截（提示"无法验证开发者"）。解决：右键 Lingutribe.app → 选「打开」，或在终端执行 xattr -dr com.apple.quarantine /Applications/Lingutribe.app 后正常打开。
  • 打包版无需安装 Node/ffmpeg/yt-dlp：ffmpeg 随包携带；模型与资料库自动写入 ~/Library/Application Support/Lingutribe/（模型目录 models/、资料库 library/），不会写入只读的应用包。

4. 默认引擎一览

能力默认引擎默认地址 / 模型是否需联网
STT 语音识别本地 Whispertiny/base/small/medium/large否（模型本地）
TTS 语音合成本地 Kokoro82m-v1.0-quantized否
LLM 大模型Ollama（本地）http://localhost:11434/v1 · 模型 qwen3:0.6b否（若用本地 Ollama）
首次运行建议：进入"设置 → STT"与"设置 → TTS"，分别点击「Deploy locally / 部署本地」，下载 Whisper 与 Kokoro 模型（约 80MB 起）。之后语音识别与语音合成可完全离线，无需任何 API Key 或费用。

三、界面总览

左侧为导航栏（可折叠，状态保存在 localStorage["lingo-sidebar"]）。页面入口：

入口路由用途
资源（音频 / 视频）/resources/audio · /resources/video导入/播放/转写音视频
阅读/read导入/朗读文章（只读 + Markdown 展示）
生词/words生词本管理
笔记/notes笔记列表 + Markdown 编辑器（Apple 备忘录式，见第十四章）
对话/chat自由 AI 对话
设置/settings引擎 / 外观 / 存储配置

外观与语言

  • 主题：设置 → 系统 → 外观，可选浅色 / 深色 / 跟随系统，存于 lingo-theme。
  • 界面语言：设置中可切换 中文 / English（存于 lingo-ui-lang），切换后应用会重新加载。
  • 学习语言 / 母语：设置中可填（默认学习语言 en、母语 zh）。这两个值会替换语法/词典提示词模板里的 {L}（学习语言）与 {N}（母语）占位符。

四、资料库（Library）结构

所有用户数据保存在"资料库"根目录，源码运行版默认 ~/Documents/LingoLibrary，可在设置 → 系统 → 存储中修改 libraryPath（打包版默认 ~/Library/Application Support/Lingutribe/library）。结构如下：

~/Documents/LingoLibrary/
├── audio/            # 导入的音频资源文件
├── video/            # 导入的视频资源文件
├── read/             # 导入的文本/文章资源
├── tts/              # 保存的 TTS 音频（开启"保存到磁盘"时）
├── dictionaries/     # 用户放入的离线词典 .mdx（及发音包 .mdd）
├── data/
│   └── models/       # Whisper / Kokoro 模型缓存（重定向至此，不落系统默认目录）
└── (SQLite 库)       # resources / words / notes / settings / chat_messages 等表
  • 磁盘用量：设置 → 系统 → 存储 会显示总空间、已用、剩余，以及各资源类型占用字节（来自 GET /api/disk）。
  • 改库路径：修改 libraryPath 并保存；新路径若不存在会自动创建所需子目录。已有数据不会自动迁移，需自行移动文件。

五、资源页（音频 / 视频）

路径 /resources/audio 与 /resources/video，用于导入并学习音视频材料。

5.1 导入材料

  • 本地文件：点击上传，单个文件上限 500MB（express.json 上限 50MB，媒体走 multer 大文件通道）。
  • URL 导入：粘贴视频/播客链接，后端用 yt-dlp 下载；可用时自动抓取字幕。失败回退到 RSS/直链。
  • 导入后在左侧列表中显示，点击进入播放/学习视图。

5.2 转写（Transcribe）

  • 资源头部有 Transcribe / Re-transcribe 按钮：调用本地 Whisper 生成逐字稿，结果含时间轴（每个词有起止时间）。
  • 转写结果保存在资源的 transcript 字段（可编辑后 PUT 回 /api/resources/:id）。
  • 若未安装 ffmpeg 或 Whisper 模型未部署，转写会失败——请先完成"部署本地"步骤。

5.3 播放器与波形

  • 播放 / 暂停：按 空格 切换（在输入框/可编辑区时不触发）。
  • 语速：0.5×–2× 调节。
  • 波形面板：可缩放（20–600 像素/秒）、自动滚动开关、音高显示（用 Pitchfinder YIN 估算基频 F0 画在波形上）、区域（Regions）：拖拽创建、编辑模式下双击删除；高度可调并记忆。波形区域可用箭头按钮折叠/展开。
  • 视频分屏：视频资源支持拖拽分隔条调整画面/字幕比例，比例记忆。
  • 自动滚动与波形显隐状态均会本地记忆。

5.4 逐字稿（Transcript）

  • 布局切换：Flow（段落流式）与 Subtitle（一句一行），状态存于 lingo-transcript-view。
  • 点击单词：在右侧面板打开词典；若该词有时间戳，点击会跳转到对应播放位置。
  • 划词浮层：在 Flow 模式选中文本，浮出 Ask AI / Copy 按钮（资源页浮层；阅读页另有 Read 朗读按钮，见第七章）。
  • COCA 词频着色：单词按词频带染色（见第十二章），高频/低频一目了然。
  • 字幕断句优化（v0.1.2）：字幕分段按三条规则自动生成——① 语音段最长 10 秒；② 不足 4 秒的短句自动并入相邻字幕段（作为下一段的开头）；③ 静音超过 9 秒强制切分，小于该值尝试并入相邻段。长音频的字幕因此更整齐、不碎句。

5.5 词汇档案（Layout 标签）

  • 资源视图的 Layout 标签展示词汇难度档案（VocabProfile）：总词数、去重词数、停用词占比、以及难度评分（高频前 3k 词 + 停用词占比越高越简单）。
  • 下方按 COCA 词频带列出单词，点击单词可查词典。
  • 该标签内还有 COCA 词频带过滤开关，可显示/隐藏指定词频带。

六、阅读页（Read）

路径 /read，用于导入并精读文章。

  • 导入：支持导入本地文本文件（.txt / .md / .markdown）或粘贴网页 URL；URL 导入会自动清洗出正文（Mozilla Readability，见第八章），生成 read 类型资源。
  • 只读 + Markdown 展示：文章正文不可编辑（避免误改），以 Markdown 排版渲染——支持标题、段落、列表、表格、代码块、引用等；换行与段落间距自动优化。
  • 划词工具条：选中任意文本，浮出 复制 / Ask AI / 朗读 三个按钮（见第七章）。
  • 朗读（Read aloud）：工具栏 Read aloud 按钮朗读整篇文章；朗读时按句子逐句高亮（CSS Custom Highlight API），上方显示进度条与"第 N 句 / 共 M 句"。
  • 点击单词查词典：单击任意单词，右侧打开词典面板。
  • Layout 标签：同资源页，展示词汇难度档案与词频过滤。

七、划词工具条（复制 / Ask AI / 朗读）

在阅读页或资源页逐字稿中选中文本，会弹出一个跟随选区的浮动工具条：

按钮作用
Copy把选中的文本复制到系统剪贴板
Ask AI右侧切到 Ask AI 标签，自动带入选中文本与所在文章上下文（见第十章）
Read（仅阅读页）用默认 TTS 引擎朗读选中的文本——只读这一小段，不朗读全文
  • 出现条件：选中至少 2 个字符的文本（单词单击不触发，单击是查词典）。
  • 智能定位：工具条默认显示在选区下方；若底部空间不足会自动翻转到选区上方，并防止超出屏幕左右边缘。
  • 自动关闭：点击工具条外部、页面滚动或窗口缩放时自动收起。
  • 朗读实现：朗读走实时合成（save:false，音频仅在内存、不落盘），支持"选中即读"；资源页逐字稿浮层为 Ask AI / Copy 两个按钮（无 Read）。

八、新闻 URL 导入（Readability 清洗）

从阅读页以 URL 导入新闻/博客文章时，后端用 Mozilla Readability 自动提取正文：

  • 原理：Readability 按文本密度（正文长度 vs 标签数量）与标点密度给页面 DOM 节点打分，挑选最"像正文"的子树——广告、导航栏、侧边栏、页脚、评论、推荐位等噪音被自动剔除。
  • 护栏：若提取出的正文过短（不是真正的文章页面，如门户首页），会自动回退用原始 HTML导入，避免"导入了个空壳"。
  • 标题：依次使用 Readability 提取的标题 → 页面 <title> → 域名，保证资源名合理。
  • 段落结构保留：正文按段落、标题、列表等块级结构转换为纯文本（块之间自动空行），导入后仍是分段的可读文章，而不是一大坨文字。
  • 本地文件（.txt / .md）导入不走 Readability，原样入库。

九、离线词典（Dictionary）

Lingutribe 的词典查询100% 离线，基于 MDict 格式。

9.1 放入词典

  • 将 .mdx 词典文件（可选配套发音包 .mdd）放入资料库的 dictionaries/ 目录：~/Documents/LingoLibrary/dictionaries。
  • 后端每次查询会扫描该目录，新增/删除词典立即生效，无需重启。
  • 若查不到词，词典面板会提示：No local dictionary entry. Drop a .mdx file into …/dictionaries。

9.2 查询与展示

  • 在逐字稿/文章中点击任意单词即打开词典面板（右侧）。
  • 结果以牛津式卡片呈现：单词、音标、按词性（POS）分组，每组最多 2 条释义（英+中）+ 最多 2 个例句。已清理 ★ 与冗余 HTML。
  • 发音音频：若 .mdx 配有 .mdd 发音包，词典面板可播放发音；无发音包则返回 404（不影响文字查询）。
  • 词形还原：查不到原词时，会尝试还原词形（含不规则动词表）再查，例如 running → run。

9.3 LLM 兜底

查不到时自动用大模型：当本地词典返回 found:false，词典面板会自动调用大模型生成简洁双语释义（2 个解读 + 词性 + 2 个例句，控制在 150 词内，词典风格）。提示词默认模板支持 {WORD}/{L}/{N} 占位符，可在设置中覆盖。

9.4 词典设置（多词典选择 / 打开目录）

  • 路径 设置 → 词典（Dictionary）：列出已安装的词典，并提供 Test install（检测）与 Reveal folder（在文件管理器中打开词典目录，一键直达）两个按钮。
  • 多词典选择：装了多个 .mdx 时，可下拉指定用哪本词典解读单词；选择 Auto（默认）则依次搜索所有词典、取第一个能查到的结果。
  • 查询结果卡片会标注来源词典名（— 词典标题），方便确认用的是哪一本。

9.5 加入生词本

  • 词典面板有 "+ Add to Words" 按钮，一键把当前词加入生词本（见第十三章）。

十、Ask AI 与对话

Lingutribe 提供两种与本地大模型对话的入口，二者都依赖你在"设置 → LLM"中配置并默认的模型。AI 回复一律以 Markdown 渲染（标题/段落/列表/表格/代码块/加粗/链接等，见 lib/markdown.ts），不再是"一大段纯文本"。渲染前对内容做 HTML 转义，杜绝 XSS。

10.1 右侧 Ask AI 标签（划词提问）

  • 入口为右侧面板的第三个标签（位于 Dictionary、Grammar 之后）。
  • 在资源页（音频/视频）或阅读页选中文本 → 浮出工具条 → 点 Ask AI → 右侧切到 Ask AI，并自动带入选中文本与所在文章上下文。
  • 系统提示词会包含文章上下文（最多约 4000 字符）+ 你的选中内容，使回答贴合材料。
  • 对话持久化：每个材料/文章的对话按 thread 隔离，存于 chat_messages 表。音视频按资源 id 为 thread，阅读按文章 id 为 thread。下次打开同一材料，历史仍在。
  • 消息操作：每条 AI 回复右上角有复制 / 删除按钮。

10.2 独立对话页（Chat）

  • 路径 /chat，自由聊天，不绑定具体材料。
  • 每条对话以 notes 行存储，body 为消息数组（{role, content}）。
  • Markdown 渲染：AI 回复按 Markdown 排版显示（代码块、表格、列表均支持）。
  • 每条消息可复制 / 删除（删除仅从记录移除，不影响模型）。
  • Enter 发送，Shift+Enter 换行。
  • 系统上下文由"学习语言/母语"设置构建。

十一、语法分析（Grammar）

  • 右侧面板的 Grammar 标签 提供 "Analyze with AI" 按钮。
  • 对单个词：分析其所在上下文句子；对划选文本：分析整段选区。
  • 后端 POST /api/llm/analyze 使用默认语法提示词，分三部分输出：句子结构 / 语法 / 词汇短语；提示词中的 {L}/{N} 由语言设置替换。
  • 自定义提示词：设置 → LLM → 语法提示词文本框，可编辑并"保存提示词"。

十二、COCA 词频

COCA（Corpus of Contemporary American English）词频数据用于评估文章难度与重点词汇。

  • 数据来自 data/coca-bands.json（Nation & Crabbe BNC/COCA 25k 词表，取前 10k 频段，共 10,006 个词头），含每个词的排名与词频带阈值。
  • 词频带划分与配色：
    词频带含义颜色
    1k最高频前 1000绿
    3k前 3000黄绿
    5k前 5000蓝
    6k前 6000黄
    6k+6000 以外（低频/生词）红
  • 词形还原：查询排名时按"缩写→前缀→后缀→剥离"逐级尝试（有深度限制），并内置不规则动词表。
  • 显示位置：逐字稿单词染色、词汇档案难度评分、词典面板头部"COCA {band}（真实排名）"徽标、生词本过滤。
  • 过滤：逐字稿/词汇档案中的词频带过滤开关可控制显示哪些带，偏好存于 localStorage["lingo-coca-bands"]。

十三、生词本（Words）

  • 路径 /words，网格展示生词卡片，按 COCA 词频带染色。
  • 增删：词典面板"+ Add to Words"加入；页面内可手动添加/删除。
  • 搜索与过滤：搜索框 + 按词频带（band）过滤的筛选条。
  • 点击卡片：打开仅词典视图查词。
  • 复习字段：生词表含 level（0=新词，越高越熟）与 reviewedAt，即间隔重复（spaced repetition）的数据库骨架已存在，但目前尚未构建复习/训练界面与逻辑（见"未实现功能"）。

十四、笔记（Notes）

v0.1.2 新增。笔记以 Markdown 正文存于本地 SQLite（notes 表），界面风格类似 Apple 备忘录：左侧列表 + 右侧编辑器。

14.1 笔记页

  • 路径 /notes（左侧导航"笔记"）：左侧为笔记列表（按创建时间倒序，列表项即笔记标题），右侧为编辑器（顶部标题 + 删除按钮，正文为 Markdown 文本框）。
  • 新建：点 + New 开始新笔记；保存：点 Save 写入数据库。
  • 列表项悬停可删除该笔记。

14.2 内联笔记（播放器 / 阅读器）

  • 音频 / 视频播放器顶部工具栏、以及阅读页顶部"Read aloud"旁的笔记本图标，点击后在内容区下方展开一个内联笔记编辑区。
  • 该笔记自动关联当前资源（resourceId）：首次打开自动创建（默认标题为资源名），之后再打开直接载入已有内容。
  • 自动保存：停止输入约 0.6 秒后自动写入数据库，无需手动保存；关闭/切换资源时也会刷新未保存内容。
  • 内联笔记会同步出现在 /notes 列表中——两者读写的是同一份数据。

十五、设置总览

路径 /settings，左侧分类：系统 / STT / TTS / 词典 / LLM。界面语言可在此切换中/英，切换后重载应用。

分类可配置项
系统外观（浅/深/跟随）、界面语言、学习语言、母语、资料库路径、磁盘用量
STTWhisper 模型、部署本地、保存、测试、历史

词典检测安装（Test install）、Reveal folder 打开词典目录、选择当前使用的词典（Auto/指定）
LLM引擎（Ollama/OpenAI）、地址/模型/Key、确认、测试、语法提示词、配置列表

十六、语音识别 STT

  • 引擎：本地 Whisper（通过 echogarden），无需任何 API Key，与 LLM/TTS 完全隔离。
  • 模型：tiny / base / small / medium / large。选 large 实际映射到 large-v3-turbo。模型越大越准但越慢。
  • 部署本地：点击"Deploy locally"触发 /api/models/ensure 下载对应 Whisper 包（首次从 HuggingFace 下载）。
  • 保存 / 测试：保存把配置追加进 sttHistory；测试调用 /api/engines/stt/test 校验模型是否已就位。
  • 历史配置：点击加载、✕ 删除。STT 无拖拽排序（单一本地引擎，通常无需多配置）。

十七、语音合成 TTS

TTS 提供两种引擎，可在设置中切换：

17.1 Kokoro（本地，推荐，免费离线）

  • 神经网络 onnx 模型，完全本地，输出 WAV，不消耗任何费用或账号。
  • 模型：82m-v1.0-quantized（约 80MB，默认）/ 82m-v1.0-fp32（约 330MB，更高质量）。
  • 男声/女声：从 GET /api/tts/voices 按性别+英语筛选（声音需用完整 id，如 en-US-Heart）。
  • 部署本地："Deploy locally" 下载 Kokoro 模型+声音，并自动将其注册为默认 TTS 配置。

17.2 OpenAI 兼容（通用）

  • 填写 Base URL + API Key + 模型 + 男声/女声名字，适配 OpenAI 及多数自托管/开源 TTS（CosyVoice、GPT-SoVITS、XTTS、F5-TTS、Bark 等，均暴露 /v1/audio/speech）。
  • 输出 WAV。

17.3 TTS 配置列表与默认规则

  • 每个引擎可"保存"为一个配置项，带自己的 Base URL / API Key / 模型 / 男声 / 女声。
  • 拖拽排序：列表项可拖动；排在第一位 = 默认（带"Default"徽标）。
  • 点击配置：会把该配置的全部字段（含 URL/Key）载入表单——切换引擎配置时表单不再串用别的配置的值。
  • 保存到磁盘：勾选后 TTS 音频写入资料库 tts/ 目录（否则仅实时返回，不落盘）。
  • 测试：点击 Test 用当前表单配置（所见即所测）调用 /api/engines/tts/test（实时合成、不保存）。

十八、大语言模型 LLM

LLM 驱动 Ask AI、语法分析、词典兜底与对话页。提供两种引擎：

17.1 Ollama（本地）

  • 默认 baseUrl = http://localhost:11434/v1，模型如 qwen3:0.6b。需你本地启动 Ollama 且监听该地址（注意默认端口是 11434，不是 8080）。
  • 本地运行无需 API Key。

17.2 OpenAI 兼容（云端，如 DeepSeek）

  • 填写 Base URL + 模型 + API Key，适配 OpenAI、DeepSeek 等。
  • 例如 DeepSeek：Base URL https://api.deepseek.com/v1，模型 deepseek-chat（或你账号支持的模型名）。

17.3 LLM 配置列表与默认规则

  • "Confirm" 把当前表单保存为一个配置项，并置为默认（最新保存的 = 默认）。
  • 拖拽排序：列表项可拖动，第一位 = 默认；点击加载，✕ 删除。
  • 每配置自带 Key：保存时会把当前 API Key 一起存入该配置。点击某配置时，Base URL、模型、API Key 都会一起载入表单——切换 gemma/deepseek 等不同模型，Key 不再串用。
  • 列表项显示 🔑 API key saved（该配置自带 Key）或 🔓 no API key（无自带 Key，使用表单里的 Key）。
  • 测试：Test 用当前表单配置发送 "hi" 调用 /api/engines/llm/test，返回预览文本。

十九、引擎分离与默认规则（重要）

  • 三类引擎严格分离：STT（engines.stt，本地 Whisper，无 Key、无列表）、TTS（ttsHistory + defaultTtsId）、LLM（llmHistory + defaultLlmId）各自独立，互不影响。
  • 默认 = 列表第一项：TTS/LLM 的默认配置由列表"第一位"决定（defaultTtsId/defaultLlmId 标记激活项），真实调用经 resolveTts/resolveLlm 取值。
  • 凭证不串用：resolveLlm 仅使用该配置自己存的 Key（h.apiKey ?? undefined），绝不回退到共享的 live 字段。因此默认模型只会用自己配置的 Key，不会被上一个模型的 Key 污染。
  • 所见即所测：设置页的 Test 按钮发送当前表单里的配置，服务端测试端点接受可选 config 体——你屏幕上看到什么，就测什么。
  • 词典离线：本地词典查询（MDict）完全不联网，不涉及任何 Key。

二十、启动 / 停止 / 部署

常用命令（源码运行）

npm run build     # 构建前端到 dist/
npm run start     # 启动后端（端口 8787，可用 PORT 覆盖）
npm run dev       # 开发模式：后端 + 前端热更新（8787 live-mirror 5173）
npm run app       # Electron 桌面壳（开发模式）
npm run dist:mac  # 一键打包 macOS dmg（build + build:server + rebuild + electron-builder）
npm run typecheck # 类型检查（tsc --noEmit）

停止与重启

# 停止（释放 8787 端口）
pkill -9 -f "tsx src/server/index.ts"
lsof -ti tcp:8787 | xargs -r kill -9

# 重启
nohup npm run start >/tmp/lingo-server.log 2>&1 &

健康检查

curl http://localhost:8787/api/health   # 返回 {"ok":true}

桌面安装包说明

  • 打包原理：后端用 esbuild 打成单文件 dist-server/index.mjs，Electron 壳直接 import 它——运行时不需要 npm / tsx / Node 环境；原生模块（better-sqlite3、onnxruntime）在打包时已按 Electron 的 ABI 重建。
  • 数据目录：打包版自动把模型与资料库重定向到 ~/Library/Application Support/Lingutribe/（models/ 与 library/），ffmpeg 随包携带。
  • 单实例：重复打开会聚焦已有窗口；后端已在 8787 运行时，仅打开窗口、不重复启动。
  • 未签名提示：测试版未签名，Gatekeeper 可能拦截，右键"打开"或执行 xattr -dr com.apple.quarantine 解决（见第二章）。正式版将做 Developer ID 签名 + 公证。
Electron 两种模式：开发模式（npm run app）把 npm run start 作为子进程拉起；打包模式壳直接 import 预编译的服务端文件。两者都会等健康检查通过后再开窗。若后端已在运行，壳仅打开窗口。退出时壳会结束后端子进程。

二十一、常见问题排查

TTS Test 失败

  • No matching voice found（Kokoro）：声音字段需用完整 id（如 en-US-Heart），且模型需已部署（先点"Deploy locally"）。
  • 其他连接错误：检查该配置的 Base URL 是否正确、模型是否已部署。Kokoro 为本地引擎，无需任何 Key。

LLM Test 失败

  • 连接不上（empty response / cannot connect）：本地 Ollama 未启动，或监听地址与配置不一致（默认 11434，不是 8080）。启动 Ollama 后把对应配置拖到第一位（默认）。
  • 401 invalid key：API Key 错误或未填。确认该配置自带正确的 Key（点击配置，Key 字段应已载入）。
  • 切换模型 Key 不跟随：旧版本有此 bug（点击 gemma 仍用 deepseek 的 Key）。当前版本已修复——每个配置自带 Key，切换时表单的 URL/模型/Key 一起更新；保存（Confirm）会把 Key 绑定进该配置。

转写/导入失败

  • 源码运行版确认已安装 ffmpeg（且被应用找到）；URL 导入还需 yt-dlp。打包版两者已内置/随包。
  • Whisper 模型未部署：到设置 → STT 点"Deploy locally"。
  • URL 导入的内容很少或不像正文：Readability 把页面判为"非文章"时会回退用原始 HTML，某些特殊页面（动态渲染、需要登录、正文极短）清洗效果有限，属预期行为。

阅读页相关问题

  • 正文不能编辑？——设计如此：文章是只读的，避免误改；需要摘录时选中文本用工具条的 Copy / Ask AI / Read。
  • 选中文字没有浮出工具条？——确认选中了至少 2 个字符，且不是在输入框里；单击单词不弹工具条（那是查词典）。
  • AI 回复显示为"原始符号"（如 **、#）？——当前版本 AI 回复按 Markdown 渲染；若看到原始符号，说明模型返回的文本本身不标准，属个别模型行为。

词典不显示

  • 确认 .mdx 放在资料库的 dictionaries/ 目录；新增后无需重启，下次查询即生效。
  • 装了多本词典时，可在 设置 → 词典 指定用哪本解读（或 Auto 自动选第一个能查到的）。
  • 若查不到，面板会提示放入 .mdx 的路径，并可自动走 LLM 兜底。

打包版相关

  • 打开一片黑 / 无任何界面：早期旧包（v0.1.0 之前）有该问题（dist 路径 + undici 版本，均已修复）。请确认用的是最新 dmg；若仍黑屏，终端执行 lsof -ti tcp:8787 查看是否有残留进程占用端口，退出重开应用。
  • 首次打开提示"无法验证开发者"：未签名测试版所致，右键 →「打开」或执行 xattr -dr com.apple.quarantine /Applications/Lingutribe.app。
